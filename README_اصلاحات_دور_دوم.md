# راهنمای اصلاحات دور دوم (هدر + فرم‌ها)

## علت اصلی مشکلات

۱. فایل `header-hero-v2.css` قبلاً فقط در `extra_css` صفحه‌ی اصلی (`home.html`) لود می‌شد.
   در نتیجه در بقیه‌ی صفحات هدر بدون استایل رندر می‌شد و منوها به‌صورت لیست بولت‌دار
   زیر هم می‌افتادند. **همین موضوع، علت اصلی «به‌هم‌ریختگی هدر در همه‌ی صفحات غیر از
   صفحه اصلی» بود.**

۲. در ردیف دوم هدر از `justify-content: space-between` استفاده شده بود که باعث می‌شد
   منوهای «حساب کاربری من / تماس با ما / وبلاگ» با فاصله‌ی زیاد از «دسته‌بندی کالاها»
   به انتهای دیگر سطر پرتاب شوند، نه بلافاصله بعدش.

۳. دکمه‌ی ورود، وقتی کاربر لاگین بود، فقط نام کاربری (مثلاً «admin») را نشان می‌داد
   و هیچ دکمه‌ی خروجی طراحی نشده بود.

۴. چند قالب (تماس، استعلام قیمت، استخدام) فیلدهای فرم را با `{{ field }}` خام رندر
   می‌کنند (بدون کلاس `form-control`)، پس هیچ استایلی روی آن‌ها اعمال نمی‌شد.

## فایل‌های تغییریافته -- جایگزین مستقیم کنید

| فایل | محل قرارگیری |
|---|---|
| `templates/base.html` | جایگزین فایل موجود `templates/base.html` -- **مهم‌ترین تغییر همین است**: لینک `header-hero-v2.css` از `home.html` به اینجا (سراسری) منتقل شد. |
| `templates/partials/header.html` | جایگزین فایل موجود -- اضافه‌شدن دکمه‌ی خروج + اصلاح ترتیب منوها |
| `templates/core/home.html` | جایگزین فایل موجود -- بلوک `extra_css` حذف شد چون دیگر لازم نیست (CSS حالا سراسری است) |
| `static/css/header-hero-v2.css` | جایگزین فایل موجود -- شامل ۳ دسته اصلاح: |

### تغییرات داخل `header-hero-v2.css`
- `.header-nav-inner`: از `justify-content: space-between` به `justify-content: flex-start` + `gap: 2rem` تغییر کرد تا منوها بلافاصله بعد از «دسته‌بندی کالاها» بیایند.
- بخش جدید `.header-user-menu`, `.header-logout-form`, `.header-logout-btn`: استایل دکمه‌ی خروج (قرمز، کنار نام کاربر).
- بخش جدید در انتهای فایل (`رفع به‌هم‌ریختگی فرم‌ها`): تمام `input`, `select`, `textarea` داخل هر `<form>` درون `.form-card` را -- حتی بدون کلاس `form-control` -- استایل می‌دهد. این یعنی صفحات تماس، استعلام قیمت، استخدام، ثبت‌نام و... بدون نیاز به تغییر تک‌تک قالب‌هایشان درست می‌شوند.

### تغییرات داخل `header.html`
- وقتی کاربر لاگین است: کنار نام کاربری، یک دکمه‌ی «خروج» (فرم POST به `accounts:logout`، چون در Django 6 دیگر GET برای Logout مجاز نیست) نمایش داده می‌شود.
- وقتی کاربر مهمان است: همان دکمه‌ی «ورود | ثبت‌نام» که به صفحه‌ی ورود می‌رود؛ از همان صفحه لینک «ثبت‌نام کنید» هم موجود است (قالب `accounts/login.html` از قبل این لینک را دارد، نیازی به تغییر نبود).

## هیچ تغییری در این فایل‌ها لازم نیست
- `apps/accounts/urls.py`, `apps/accounts/views.py` -- منطق ورود/ثبت‌نام/خروج از قبل صحیح بود.
- `templates/accounts/login.html`, `templates/accounts/register.html` -- از قبل درست کار می‌کردند.

## بعد از جایگزینی فایل‌ها
هیچ migration یا دستور جدیدی لازم نیست (این دور فقط تغییرات Template/CSS بود).
کافیست کش مرورگر را خالی کنید (Ctrl+F5) تا CSS جدید در همه‌ی صفحات لود شود.

## اگر باز هم فرمی به‌هم‌ریخته دیدید
اگر بعد از این اصلاح، فرم خاصی هنوز درست نبود (مثلاً چون کلاً خارج از `.form-card` است)،
دو راه دارید:
1. ساده‌ترین راه: در آن قالب، فیلد را داخل یک `<div class="form-card">...</div>` بگذارید.
2. یا به من بگویید کدام صفحه دقیقاً، تا انتخاب‌گر CSS دقیق همان مسیر را هم اضافه کنم.
