# راهنمای اصلاحات دور هشتم (بخش «محتوای سایت» در داشبورد)

## علت مشکل

اپ `apps.core` مدل‌های مهمی دارد که محتوای عمومی سایت را می‌سازند: تنظیمات
سایت، اسلایدر بنر صفحه اصلی، بنرهای تبلیغاتی، آمار، گواهینامه‌ها، برندهای
همکار، نظرات مشتریان، سوالات متداول و منوها. همه‌ی این‌ها در Django Admin
(`/admin/`) از قبل ثبت‌شده و قابل مدیریت بودند (`apps/core/admin.py`) --
اما **داشبورد اختصاصی خودتان** (`/dashboard/`) هیچ صفحه‌ای برای مدیریت
هیچ‌کدام از این‌ها نداشت. سایدبار داشبورد فقط به محصولات/خدمات/پروژه‌ها/
وبلاگ/گالری/سفارشات/صندوق ورودی دسترسی می‌داد، و برای این‌ها فقط لینک
«پنل ادمین کامل (Django Admin)» وجود داشت که کاربر باید به رابط خام و
کمتر کاربرپسند جنگو می‌رفت.

## اصلاح

یک بخش کامل جدید به نام **«محتوای سایت»** به سایدبار داشبورد اضافه شد که
مستقیماً همان استایل و تجربه‌ی بقیه‌ی بخش‌های داشبورد را دارد (نه Django
Admin خام):

| صفحه‌ی جدید در داشبورد | آدرس | مدل مرتبط |
|---|---|---|
| تنظیمات سایت | `/dashboard/site-settings/` | `SiteSetting` (Singleton -- فرم ویرایش، بدون لیست چون فقط یک رکورد است) |
| اسلایدر صفحه اصلی | `/dashboard/home-slides/` | `HomeSlide` |
| بنرهای تبلیغاتی | `/dashboard/promo-banners/` | `PromoBanner` |
| آمار صفحه اصلی | `/dashboard/statistics/` | `Statistic` |
| گواهینامه‌ها | `/dashboard/certificates/` | `Certificate` |
| برندهای همکار | `/dashboard/partners/` | `Partner` |
| نظرات مشتریان | `/dashboard/testimonials/` | `Testimonial` |
| سوالات متداول | `/dashboard/faqs/` | `FAQ` |
| منوهای هدر/فوتر | `/dashboard/menus/` | `Menu` |

همه‌ی این‌ها (به‌جز تنظیمات سایت که Singleton است) الگوی یکسان
افزودن/ویرایش/حذف دارند و از همان قالب‌های عمومی موجود در پروژه
(`dashboard/generic_form.html` و `dashboard/confirm_delete.html`) استفاده
می‌کنند -- هیچ الگوی جدیدی به پروژه اضافه نشد، فقط از همان الگوی خودتان
پیروی شد.

## یک اصلاح جانبی مهم (باگ واقعی که در همین فایل پیدا شد)

لینک «خروج» در سایدبار داشبورد یک لینک ساده (`<a href="...">`) بود، اما
از Django 5 به بعد `LogoutView` دیگر درخواست GET را قبول نمی‌کند (باید POST
باشد) -- یعنی این دکمه در پروژه‌ی شما (Django 6.0.7) اصلاً کار نمی‌کرد و
با خطای ۴۰۵ مواجه می‌شد. همراه با این تغییرات، آن را هم به یک فرم POST
(دقیقاً مثل دکمه‌ی خروج در هدر سایت) اصلاح کردم.

## فایل‌های تغییریافته/جدید -- محل قرارگیری

| فایل | نوع | محل قرارگیری |

همان `dashboard/generic_form.html` موجود استفاده می‌کند.

## نیازی به Migration نیست
این دور فقط View/URL/Template اضافه شد، مدلی تغییر نکرد.

## تست پیشنهادی
با یک کاربر مدیر وارد `/dashboard/` شوید و مطمئن شوید بخش «محتوای سایت» در
سایدبار دیده می‌شود؛ روی «اسلایدر صفحه اصلی» کلیک کنید و یک اسلاید تست
اضافه کنید -- باید بلافاصله در صفحه‌ی اصلی سایت (بنر بالای صفحه) دیده شود.
همین‌طور «تنظیمات سایت» را باز کنید و مطمئن شوید مقادیر فعلی (نام سایت،
تلفن و ...) در فرم از قبل پر شده‌اند.
