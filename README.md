# سامان تجهیز اسپادان — وب‌سایت شرکتی صنعتی

پروژه Django برای شرکت طراحی و ساخت تابلوهای برق صنعتی «سامان تجهیز اسپادان».
معماری این پروژه از ابتدا برای تبدیل آینده به فروشگاه آنلاین کامل (بدون نیاز به بازطراحی) در نظر گرفته شده است.

## وضعیت فعلی پروژه (فاز ۱ و ۲ از فازبندی کامل)

✅ فاز ۱ -- طراحی معماری و دیتابیس: مدل‌های تمام اپ‌ها طراحی و اعتبارسنجی شد (migrate موفق).
✅ فاز ۲ -- اسکلت پروژه Django: تمام اپ‌ها (core, accounts, products, services, projects, blog,
gallery, contact, pages, dashboard) با URL، View و Admin پایه ایجاد و تست شدند (تمام صفحات HTTP 200).

✅ فاز ۳ -- طراحی UI/UX: طراحی گرافیکی کامل با پالت سرمه‌ای/نارنجی/سفید/خاکستری روشن مطابق هویت
بصری شرکت. هیرو، آمار، کارت‌های خدمات/محصولات/پروژه‌ها، گواهینامه‌ها، نظرات مشتریان، سوالات متداول،
صفحه درباره‌ما کامل، فیلتر محصولات/پروژه‌ها/وبلاگ، فرم‌های تماس/استعلام قیمت/استخدام، صفحه ۴۰۴
سفارشی و انیمیشن AOS در همه صفحات پیاده‌سازی و روی SQLite تست شد (تمام صفحات کلیدی HTTP 200).

✅ فاز ۴ -- پنل مدیریت اختصاصی: داشبورد کامل با سایدبار مدیریتی (`/dashboard/`) جدا از Django Admin
پیش‌فرض، شامل: مدیریت محصولات و دسته‌بندی‌ها (افزودن/ویرایش/حذف)، خدمات، پروژه‌ها، مقالات وبلاگ،
گالری، فرصت‌های شغلی، و صندوق‌های ورودی عملیاتی (پیام‌های تماس، استعلام قیمت، استعلام محصول،
درخواست استخدام) با قابلیت علامت‌گذاری خوانده‌شده/پردازش‌شده. دسترسی بر اساس نقش کاربر
(`StaffRequiredMixin`) محدود شده و کاربران غیرمدیریتی دسترسی ندارند. تمام ۱۹ مسیر داشبورد با
شبیه‌سازی ورود کاربر مدیر تست شد (HTTP 200) و عملکرد ایجاد رکورد واقعی (دسته‌بندی محصول) نیز
تأیید شد. Django Admin پیش‌فرض همچنان برای مدیریت پیشرفته‌تر (مثل کاربران و مجوزها) در دسترس است.

✅ فاز ۵ -- تکمیل سیستم محصولات: فیلتر و جستجوی زنده AJAX بدون رفرش صفحه (فیلتر دسته‌بندی، برند،
محدوده قیمت، مرتب‌سازی جدیدترین/ارزان‌ترین/گران‌ترین/نام) با بروزرسانی URL از طریق `history.pushState`
و صفحه‌بندی AJAX. جستجوی زنده با Autocomplete (پیشنهاد محصول هنگام تایپ، Debounce ۴۰۰ میلی‌ثانیه‌ای).
علاوه‌براین: **علاقه‌مندی‌ها (Wishlist)** و **مقایسه محصولات (Compare، حداکثر ۴ محصول)** به‌صورت
مبتنی بر Session (برای کاربر مهمان و عضو)، نمایش نشان وضعیت موجودی/تخفیف روی کارت محصول.
**یک باگ واقعی و مهم کشف و اصلاح شد**: تبدیل‌گر پیش‌فرض `<slug:slug>` جنگو فقط اسلاگ‌های انگلیسی را
می‌پذیرد، درحالی‌که اسلاگ محصولات/پروژه‌ها/خدمات/مقالات/صفحات به‌صورت یونیکد فارسی تولید می‌شوند --
این مورد در تمام اپ‌های مرتبط به `<str:slug>` اصلاح شد. با بیش از ۱۵ سناریوی تست عملکردی
(فیلتر، جستجو، مرتب‌سازی، Autocomplete، ویشلیست، مقایسه، اسلاگ فارسی واقعی) به‌طور کامل تأیید شد.

✅ فاز ۶ -- تکمیل سیستم پروژه‌ها: فیلتر AJAX بر اساس دسته‌بندی صنعت، سال اجرا و جستجوی متنی
(عنوان/کارفرما/محل اجرا) با مرتب‌سازی جدیدترین/قدیمی‌ترین/نام، بدون رفرش صفحه. در صفحه جزئیات
پروژه یک گالری Lightbox سفارشی (بدون وابستگی به کتابخانه خارجی) اضافه شد -- کلیک روی هر تصویر،
نمایش تمام‌صفحه با ناوبری قبلی/بعدی (کیبورد و کلیک) و کپشن باز می‌کند.
**یک باگ واقعی دیگر کشف و اصلاح شد**: فیلتر `intcomma` (جداکننده هزارگان قیمت) در صفحه جزئیات
محصول بدون بارگذاری `{% load humanize %}` استفاده شده بود که باعث خطای کامل صفحه می‌شد -- اصلاح شد
و تمام قالب‌های مشابه بررسی شدند. با ۱۱ سناریوی تست سرتاسری (محصولات، Wishlist، مقایسه محصولات،
پروژه‌ها، Lightbox) به‌طور کامل تأیید شد.

✅ فاز ۷ -- سیستم وبلاگ تکمیلی: مدل `Comment` با قابلیت پاسخ تودرتو و نیاز به تأیید مدیر قبل از
نمایش عمومی، فیلتر/جستجو/مرتب‌سازی AJAX مقالات (دسته‌بندی، برچسب، جدیدترین/قدیمی‌ترین/پربازدیدترین)،
فرم ثبت نظر و پاسخ در صفحه مقاله، و صفحه مدیریت نظرات در داشبورد (تأیید/حذف). با ۱۱ سناریوی تست
سرتاسری (شامل تأیید یک نظر واقعی از داشبورد و نمایش آن در صفحه عمومی) تأیید شد.

✅ فاز ۸ -- سئوی فنی کامل: `sitemap.xml` پویا شامل صفحات ثابت، محصولات، دسته‌بندی محصولات، پروژه‌ها،
خدمات، مقالات و صفحات پویا؛ `robots.txt` با ارجاع به Sitemap و مسدودسازی مسیرهای مدیریتی؛ متاتگ‌های
Canonical URL، Open Graph کامل (title/description/type/image) و Twitter Card در تمام صفحات از طریق
بلوک‌های قابل بازنویسی در `base.html`؛ Schema.org JSON-LD برای Organization (سراسری)، Product
(صفحه محصول، شامل قیمت و موجودی) و Article (صفحه مقاله). با ۴ سناریوی تست تأیید شد.

✅ فاز ۹ -- قابلیت فروشگاه: اپ جدید `apps/shop` با مدل‌های Cart، CartItem، Order، OrderItem و Coupon.
سبد خرید مبتنی بر Session (برای مهمان) یا کاربر واردشده، با افزودن/بروزرسانی تعداد/حذف آیتم به‌صورت
AJAX بدون رفرش صفحه، اعمال کد تخفیف (درصدی یا مبلغ ثابت)، فرآیند تسویه‌حساب و ثبت سفارش، پیگیری
سفارش با شماره سفارش + شماره تماس (بدون نیاز به ورود)، و صفحه «سفارشات من» برای کاربران واردشده.
مدیریت کامل سفارشات (مشاهده جزئیات، تغییر وضعیت: در انتظار پرداخت/در حال پردازش/ارسال‌شده/تحویل‌شده)
و کدهای تخفیف در داشبورد. یک نقطه‌اتصال مشخص و کامنت‌گذاری‌شده برای درگاه پرداخت واقعی (مثل زرین‌پال)
در `CheckoutView` تعبیه شده تا بدون بازطراحی معماری قابل افزودن باشد. با ۱۸ سناریوی تست سرتاسری
(جریان کامل خرید تا ثبت سفارش + مدیریت از داشبورد) تأیید شد. **یک باگ import کشف و اصلاح شد**
(`DetailView` در `dashboard/views.py` ایمپورت نشده بود).

✅ فاز ۱۰ -- استقرار (Deployment): `Dockerfile` چندمرحله‌ای، `docker-compose.yml` کامل (Django + PostgreSQL
+ Redis + Nginx به‌عنوان Reverse Proxy)، اسکریپت `entrypoint.sh` (انتظار برای دیتابیس، migrate خودکار،
collectstatic، اجرای Gunicorn)، پیکربندی Nginx برای سرو فایل‌های استاتیک/مدیا و پروکسی درخواست‌ها،
و WhiteNoise برای فشرده‌سازی و کش فایل‌های استاتیک در پروداکشن. **یک ناسازگاری نسخه کشف و اصلاح شد**:
نسخه Django در `requirements.txt` (5.1.4) با نسخه واقعاً نصب و تست‌شده (6.0.7) مطابقت نداشت -- اصلاح
شد. وابستگی‌های اعلامی ولی هرگز استفاده‌نشده (django-mptt، django-taggit، django-ckeditor) از
`requirements.txt` حذف شدند تا فایل با کد واقعی همخوانی داشته باشد. با اجرای کامل `collectstatic`
(۱۳۳ فایل استاتیک) و تست ۱۱ صفحه کلیدی روی سرور با WhiteNoise فعال، تأیید شد.

## استقرار با Docker (روش توصیه‌شده)

```bash
cp .env.example .env
# مقادیر SECRET_KEY، DB_PASSWORD و ALLOWED_HOSTS را در .env ویرایش کنید

docker compose up --build -d
docker compose exec web python manage.py createsuperuser
```
سایت روی پورت ۸۰ (از طریق Nginx) در دسترس خواهد بود. Migration و collectstatic به‌صورت خودکار
توسط `entrypoint.sh` در هر بار اجرا انجام می‌شود.
به‌صورت تدریجی و در ادامه همین مسیر تکمیل می‌شوند.

## نصب و راه‌اندازی

### ۱. ایجاد و فعال‌سازی محیط مجازی
```bash
python3 -m venv venv
source venv/bin/activate      # ویندوز: venv\Scripts\activate
```

### ۲. نصب پیش‌نیازها
```bash
pip install -r requirements.txt
```

### ۳. تنظیم فایل محیطی
```bash
cp .env.example .env
# مقادیر SECRET_KEY و اطلاعات دیتابیس PostgreSQL را ویرایش کنید
```

### ۴. ایجاد دیتابیس PostgreSQL     & "C:\Program Files\PostgreSQL\18\bin\psql.exe" -U postgres
```sql
CREATE DATABASE samantajhiz;
```

### ۵. اجرای Migration
```bash
python manage.py makemigrations
python manage.py migrate
```

### ۶. ساخت ادمین
```bash
python manage.py createsuperuser
```

### ۷. جمع‌آوری فایل‌های استاتیک (برای پروداکشن)
```bash
python manage.py collectstatic
```

### ۸. اجرای سرور توسعه
```bash
python manage.py runserver
```
سپس مرورگر را در آدرس `http://127.0.0.1:8000` باز کنید، و پنل ادمین در `http://127.0.0.1:8000/admin`.

## استقرار (Deployment) -- خلاصه

- `DJANGO_SETTINGS_MODULE=config.settings.prod`
- سرور WSGI: Gunicorn (در requirements.txt موجود است)
- سرو فایل‌های استاتیک: WhiteNoise یا Nginx
- دیتابیس: PostgreSQL روی سرور مجزا یا همان سرور
- HTTPS/SSL الزامی (تنظیمات امنیتی در `prod.py` فعال است)

راهنمای کامل و اسکریپت‌های Deployment در فاز ۱۰ (طبق فازبندی پروژه) ارائه خواهد شد.

## نکته مهم درباره ادامه پروژه

باقی فازها (طراحی گرافیکی کامل صفحات، پنل مدیریت اختصاصی پیشرفته با گزارش‌گیری، سیستم محصولات
با فیلتر AJAX و مقایسه، سئوی فنی کامل با Sitemap/Schema، و آماده‌سازی نهایی فروشگاه با سبد خرید

## ممیزی سناریوهای فروشگاه (Order/Stock/Concurrency/Security)

فایل `SECURITY_AUDIT.md` را ببینید -- بررسی کامل ۱۹ دسته سناریوی فروشگاه حرفه‌ای (سفارش، موجودی، همزمانی،
تخفیف، پرداخت، امنیت، اعلان، Scheduler و...) با وضعیت دقیق هرکدام (رعایت‌شده/اصلاح‌شده/نیازمند زیرساخت خارجی).

**نکته مهم Cron:** برای آزادسازی خودکار موجودیِ سفارش‌های راکد (پرداخت‌نشده)، این دستور باید طبق زمان‌بندی
(نه دستی) اجرا شود:
```bash
# هر ۵ دقیقه در crontab سرور:
*/5 * * * * cd /path/to/project && venv/bin/python manage.py cancel_stale_orders --minutes=30
```
